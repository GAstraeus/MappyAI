# Project Brief: RL Agent for NES Mappy via stable-retro

## Goal

Train a reinforcement-learning agent to play **Mappy (NES)** from **pixel observations**, using the user's own cartridge-dumped ROM (`.nes` file, legally sourced — they dumped it from their cartridge). Afterwards the user wants to **watch the trained agent play** (live window and/or recorded video).

Decisions already made with the user — do not re-litigate:

- **No game clone.** Use stable-retro with a custom integration of the real NES ROM.
- **Pixel observations** (CNN policy), not RAM/structured features. RAM features can be a later optimization.
- **PPO via Stable-Baselines3** as the algorithm.
- Target machine: the user's Mac (`darwin`, Apple Silicon assumed, zsh).

The project directory is `/Users/gdiwan/Documents/projects/mappy` (currently contains only this file). The user will supply `rom.nes` — it is **not** in the folder yet; build everything so the ROM just needs to be dropped in.

## Verified research findings (checked 2026-09-01 against Farama-Foundation/stable-retro `main`)

### Library facts
- **stable-retro** (maintained fork of gym-retro) supports **NES on macOS including Apple Silicon**, Python **3.10–3.14**. Install: `pip install stable-retro`.
- Import name is `import stable_retro as retro`. (`import retro` still works via a shim but emits a DeprecationWarning — use `stable_retro`.)
- Uses the **Gymnasium API**: `step()` returns `(obs, reward, terminated, truncated, info)`.
- `retro.make(game, state=State.DEFAULT, inttype=stable_retro.data.Integrations.DEFAULT, **kwargs)`. `RetroEnv.__init__` accepts: `scenario`, `info`, `use_restricted_actions` (default `Actions.FILTERED`), `record` (writes `.bk2` replay files), `players`, `obs_type` (`Observations.IMAGE` default), `render_mode` (`"human"` default, also `"rgb_array"`).
- Custom integrations: `stable_retro.data.Integrations.add_custom_path(abs_path)` then `retro.make("Mappy-Nes", inttype=retro.data.Integrations.ALL)`.
- **One emulator instance per process** — parallel envs require `SubprocVecEnv`, never `DummyVecEnv` with n>1.
- `.state` files are **gzipped emulator save states**. You can create one programmatically: boot with `state=retro.State.NONE`, step through the title screen pressing START, then `gzip`-write `env.em.get_state()` to `<Name>.state`.
- `.bk2` recordings convert to MP4 with `python -m stable_retro.scripts.playback_movie <file>.bk2` (requires ffmpeg).
- `env.get_ram()` returns NES RAM (2KB) — useful for the score-address hunt below.
- ROM hashing (`rom.sha`, SHA1) strips the 16-byte iNES header for `.nes` files, but for a custom integration you can simply place `rom.nes` in the integration dir — `get_romfile_path` finds it directly.

### Game integration facts
- **No integration exists for original Mappy.** stable-retro *does* ship `MappyLand-Nes-v0` (the sequel) — use it as the reference template. Its complete integration is just:

  `data.json`:
  ```json
  {
    "info": {
      "lives": { "address": 80, "type": "|i1" },
      "score": { "address": 23, "type": "<u2" },
      "toys":  { "address": 1444, "type": "|u1" }
    }
  }
  ```
  `scenario.json`:
  ```json
  {
    "done":   { "variables": { "lives": { "op": "negative" } } },
    "reward": { "variables": { "score": { "reward": 10.0 } } }
  }
  ```
  Plus `rom.sha`, `metadata.json` (sets default state), and a `Level1.state`.

- **Data Crystal RAM map for Mappy (NES)** (https://datacrystal.tcrf.net/wiki/Mappy_(NES)/RAM_map) is a stub with exactly one entry: **lives = `0x0070`** (1 byte). The **score address is unknown and must be found** — this is the only real unknown in the project.

### Reference code that ships with stable-retro (adapt, don't reinvent)
- `stable_retro/examples/ppo.py` — canonical SB3 training setup: `StochasticFrameSkip(n=4, stickprob=0.25)` wrapper, `TimeLimit(max_episode_steps=4500)`, `WarpFrame` + `ClipRewardEnv` (from `stable_baselines3.common.atari_wrappers`), `SubprocVecEnv([make_env] * 8)`, `VecFrameStack(n_stack=4)`, `VecTransposeImage`, then `PPO("CnnPolicy", lr=lambda f: f*2.5e-4, n_steps=128, batch_size=32, n_epochs=4, gamma=0.99, gae_lambda=0.95, clip_range=0.1, ent_coef=0.01)`.
- `stable_retro/examples/discretizer.py` — `Discretizer(gym.ActionWrapper)` mapping a list of button combos to a `Discrete` action space (reads `env.unwrapped.buttons`).

## Plan of work

### 1. Project scaffold
```
mappy/
├── requirements.txt              # stable-retro, stable-baselines3[extra], gymnasium, opencv-python, pygame
├── mappy_env.py                  # shared env factory: registers integrations/ path, applies wrappers
├── integrations/Mappy-Nes/
│   ├── rom.nes                   # user drops this in
│   ├── rom.sha                   # generated by setup script
│   ├── data.json                 # lives @ 112 (0x70); score vars added once found
│   ├── scenario.json             # done: lives; reward: score delta
│   ├── metadata.json             # {"default_state": "Level1"}
│   └── Level1.state              # generated by play/state script
└── scripts/
    ├── setup_rom.py              # copy ROM in, write rom.sha, sanity-check env boots
    ├── play.py                   # pygame: human plays w/ keyboard; 'S' saves Level1.state; logs RAM history
    ├── find_score.py             # analyzes RAM log to locate score bytes
    ├── train.py                  # PPO training (adapted from examples/ppo.py)
    └── watch.py                  # load checkpoint, render_mode="human"; --record writes .bk2/mp4
```

### 2. Mappy-specific choices
- **Action space** (via `Discretizer`): Mappy uses only left/right movement plus one button for the micro-wave doors; trampoline bouncing is automatic. Combos: `[[], ["LEFT"], ["RIGHT"], ["A"], ["LEFT","A"], ["RIGHT","A"]]`. Verify in `play.py` whether the NES port uses A or B for doors and adjust.
- **Reward**: score delta (from `scenario.json` once score address is known). Note `ClipRewardEnv` sign-clips rewards — acceptable to start; consider scaling (e.g. delta × 0.01) instead if pair-bonus magnitudes should matter.
- **Done**: lives-based. Data Crystal doesn't document whether lives hits 0 during the last life or decrements past it — verify actual behavior with `play.py`/RAM log and pick `negative` vs `equal 0` accordingly.
- **Observations**: grayscale 84×84 (`WarpFrame`), 4-frame stack, frame-skip 4 — all per the shipped ppo.py example.

### 3. Finding the score address (the one open research task)
Suggested approach, no external tools needed:
1. In `play.py`, log `env.get_ram()` every frame while the user plays a life or two and collects items.
2. In `find_score.py`, scan the log for groups of 1–6 consecutive bytes that decode as a monotonically non-decreasing number under candidate encodings: digit-per-byte (each byte 0–9, either endianness — most likely for NES score displays), packed BCD, or plain little-endian integer.
3. Rank candidates by number-of-increases and present them with their final decoded value so the user can match it to their remembered final score.
4. If encoding is digit-per-byte (unsupported by scenario.json's type system as a single variable), register each digit byte as a separate `data.json` variable (`score0`…`score5`) and compute the score delta in a small Python `RewardWrapper` in `mappy_env.py` instead of via `scenario.json`. Keep `done` in `scenario.json`.

### 4. Save state
`play.py` lets the user play to the start of Level 1 and press a key to save `Level1.state` (gzip of `env.em.get_state()`). Boot for this via `state=retro.State.NONE`.

### 5. Training & watching
- `train.py`: 8 subprocess envs, checkpoints via `CheckpointCallback`, tensorboard logging, default `total_timesteps` ~5–10M (pixels needs millions of frames; tell the user to expect hours on a Mac CPU/MPS).
- `watch.py`: single env, `render_mode="human"`, same observation wrappers as training (model input must match), stochastic action sampling (deterministic policies tend to loop). `--record` flag: `retro.make(..., record="recordings/")` then convert `.bk2` → MP4 via `python -m stable_retro.scripts.playback_movie`.

## Gotchas checklist
- `import stable_retro as retro`, not `import retro`.
- Register the custom integration path (`Integrations.add_custom_path`) **in every process** — put it at module level in `mappy_env.py` and import that in the SubprocVecEnv env factory.
- One retro env per process (SubprocVecEnv).
- Gymnasium 5-tuple step API throughout.
- `render_mode` must be set at `make()` time (Gymnasium convention); use `render_mode=None` for training workers.
- watch/eval envs need identical observation wrappers to training.
- ffmpeg needed only for `.bk2` → MP4 conversion (`brew install ffmpeg`).
